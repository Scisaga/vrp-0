# 当前需求

## 1. 文档目的与边界

本文记录当前实现已经支持的功能要求和行为边界，作为产品定位与技术设计之间的需求事实源。

本文不复制 REST 路径和字段，不列出约束权重，不描述类或文件布局，也不收录未确认能力。精确 API 契约见 [`docs/openapi.yaml`](../openapi.yaml)。

## 2. 当前场景

* 系统应允许查询当前场景；不存在时应给出明确的缺失结果。
* 系统应允许创建或更新当前场景，导入时可按替换语义保存，并维护标识、名称及创建、更新时间。
* 系统应允许删除当前场景；删除后相关求解任务历史一并清理。
* 场景保存和读取时应保持 Agent、Ticket、POI 等对象引用的一致性。
* 求解任务处于调度中或求解中时，系统应拒绝替换或删除当前场景。
* 控制台应支持以表格维护场景内容，并支持 JSON 导入当前场景。
* 控制台新增或导入仓库、Agent、Ticket、SKU 行时，应为缺失的业务 ID 生成稳定且不重复的非空 ID；用户已提供的非空 ID 保持不变，重复 ID 在创建前拒绝。

## 3. 地图、位置与矩阵

* 系统应提供 POI 查询、地址解析和逆地址解析能力，并清楚返回地图服务不可用或调用失败。
* 保存当前场景时，系统会尝试补齐缺失的位置字段；解析失败只记录告警，不阻断普通保存。显式启用构建选项时，系统才进一步校验地图能力并完整构建 POI 与场景矩阵。
* 系统应允许在 AMap 运行模式下读取和更新 AMap 进程内路由缓存；该缓存不是当前场景 `RoutePlan.matrix` 的读写入口。
* 启动求解前，场景所需位置和矩阵必须已经构建完整；不满足时不得启动任务。
* Gateway 组件创建模式下，有业务内容的仓库、Agent 和 Ticket 必须同时具有非空地址与可解析坐标；任一位置未解析时不得提交创建任务。
* AMap 适配器的配额、密钥和地址解析配置由运行配置和控制台配额页管理，敏感值不得写入项目文档。

## 4. 求解任务

* 系统应基于当前场景创建异步求解任务，并要求合法的 ISO-8601 求解时长。
* 同一时刻只允许一个任务处于调度中或求解中；重复启动应返回冲突。
* 系统应保存任务历史，并支持查询最新任务、按标识查询、筛选列表和删除已停止任务。
* 系统应持续保存更优方案和过程指标，并在结束时保存最终方案、分数说明和完成状态。
* 系统应允许终止正在调度或求解的任务；已停止任务不得重复终止。
* 系统应拒绝直接删除正在调度或求解的任务，必须先终止。
* 应用结果前必须验证任务方案与当前场景中的 Agent、Ticket 等求解对象兼容；不兼容时不得覆盖当前场景。按产品约束只应应用已停止任务，但当前应用路径尚未显式校验任务状态，调用方不得据此在求解运行中回写场景。

## 5. 结果查看与应用

* 用户应能从任务列表进入任务详情或一张图页面。
* 任务列表首次进入时应默认查询最近七日，并展示任务名称、求解完成时间和求解分数而不展示任务 ID；桌面端应通过紧凑列宽在单屏完整展示全部列，窄屏保留局部横向滚动。
* 任务详情应展示任务元数据、状态、分数与求解过程、排程时间线、路线、工程师和工单信息；运行态任务在后台定时刷新直至进入终态，操作区不提供手动刷新、自动刷新开关或复制请求参数。
* 一张图应在深色地图与时间轴上展示已求解路线和工单执行过程；播放时只刷新 Marker 与路线等业务覆盖物，底图主题没有变化时不重复刷新地图瓦片；没有可展示结果时应给出空状态。
* 用户应能从兼容的任务结果更新当前场景，并得到明确的成功或失败反馈。
* 对外查询任务时应裁剪在途矩阵等不需要随响应传输的大对象。

## 6. MCP

* MCP 应通过 Streamable HTTP 提供 Tool 调用，不提供资源和提示词能力。
* MCP 默认关闭；启用后所有实际调用必须通过 Bearer Token 校验。
* 配置 Origin 允许列表时，不在列表中的浏览器来源应被拒绝；预检请求不应被 Bearer 校验误拦截。
* MCP Tool 与 REST 应操作同一个当前场景和求解任务状态。
* Tool 名称、参数、返回值和错误约定以 [MCP 参考](../reference/mcp.md)为准。

## 7. 浏览器控制台

* 控制台应提供当前场景、求解任务、配额和 MCP 四个主导航入口。
* 求解任务详情和一张图作为从任务列表或场景流程进入的隐藏路由存在。
* 页面应覆盖初始化、加载、空数据、操作成功和错误状态。
* 控制台应支持简体中文和英文切换；后端错误通过稳定错误码和参数本地化，不直接依赖服务端消息作为用户文案。
* 窄屏应提供移动导航，数据密集区域可滚动而不挤压内容。

## 8. 非功能边界

* 场景和任务写入应具备进程内并发保护，并使用原子文件替换降低部分写入风险。
* 测试应区分稳定单元测试、进程内应用测试、外部系统测试和手工脚本。
* 配置和文档不得包含真实地图密钥或 MCP Token。当前任务异常对象可能包含内部堆栈，相关访问边界见[安全说明](../design/security.md)。

## 9. 非目标

本文只约束上述当前能力，不据此推导新的产品能力或外部系统集成协议。
* Gateway 对话式导入必须将用户口语时间转换为 OpenAPI 规定的完整日期时间，保留真实地址及解析坐标，并向 Host 提供可读的场景大纲；不确定的日期、跨日或地址候选必须由用户确认，不得提交纯时间或编造位置。
