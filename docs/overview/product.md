# 产品定位

## 1. 文档目的与边界

本文从产品层说明 vrp-0 当前解决的问题、使用入口、核心原则、非目标和完成标准。

本文不描述 REST 字段、求解约束权重、类结构、文件布局或页面视觉细节；这些内容分别由接口、设计和 UI 文档负责。

## 2. 产品定位

vrp-0 是基于 Quarkus 与 OptaPlanner 的车辆路径与现场服务排程引擎。它接收包含车辆或工程师、工单、仓库、位置、时间和约束配置的当前场景，构建或接收在途矩阵，异步求解排程方案，并提供任务进度、结果查看和结果回写能力。

当前产品面向一个引擎实例内的一份当前场景。场景是启动求解、查看结果和应用结果的共同上下文。

## 3. 当前目标

* 维护一份可被验证和持久化的当前场景。
* 解析位置并准备求解所需的在途矩阵。
* 在明确的约束和终止时间内异步生成排程结果。
* 保存求解任务历史、状态、分数过程和最终方案。
* 通过 REST、MCP 和浏览器控制台提供一致的引擎能力。
* 允许把与当前场景兼容的任务方案应用回当前场景；按产品约束只应应用已停止任务。

## 4. 使用方式

### 4.1 REST API

供程序化调用者维护当前场景、查询地图相关数据、启动和管理求解任务。语义说明见[接口说明](../interfaces/api.md)，精确契约见 [`docs/openapi.yaml`](../openapi.yaml)。

### 4.2 MCP

以 Streamable HTTP 和 Tool 的形式暴露当前场景及求解操作，供支持 MCP 的客户端调用。接入和 Tool 契约见 [MCP 参考](../reference/mcp.md)。

### 4.3 浏览器控制台

用于维护和导入当前场景、启动求解、浏览任务历史、查看排程详情与地图，以及查看配额和 MCP 接入信息。页面行为见[前端界面说明](../interfaces/frontend.md)。

## 5. 单场景原则

* 运行实例只存在“无当前场景”或“有一个当前场景”两种情况。
* 普通保存更新同一当前场景，不创建可选择的场景集合。
* 按导入替换语义保存或删除当前场景时，既有求解任务随之清理。
* 求解运行期间，普通保存、按替换语义保存和删除当前场景都会被拒绝。结果应用按产品约束也不应在运行中执行，但当前应用路径尚未显式校验任务状态。
* 任务可以保留历史记录，但同一时刻只运行一个任务。

## 6. 当前完成标准

一次可用的端到端流程应满足：

1. 当前场景能够保存并再次读取。
2. 场景中的求解对象、位置和矩阵满足启动前置条件。
3. 求解任务能够创建、运行到结束或被终止，并可查询状态。
4. 已完成任务能够展示方案、分数与过程指标。
5. 与当前场景兼容且已经停止的任务结果能够被应用。
6. REST、MCP 与控制台观察到的当前状态一致。

## 7. 非目标

本文只定义上述当前场景及其求解任务链路，不扩展该范围之外的产品流程。
