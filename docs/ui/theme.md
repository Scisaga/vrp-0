# 界面主题

## 1. 文档目的与边界

本文记录静态控制台当前使用的视觉基础、通用布局、组件外观、响应式和可访问性约束，用于保持已有页面一致。

本文不定义页面业务流程，不要求为了统一文档而重写已有页面，也不引入新的设计系统。页面行为见[前端界面说明](../interfaces/frontend.md)。

## 2. 视觉基础

* 当前使用浅色主题，根节点声明 `color-scheme: light`。
* 桌面侧栏左上角显示 `VRP-0`，侧栏和 favicon 共用由 `VRP-0-light.png` 简化生成的本地透明背景 `vrp-0-logo.png`，浏览器标题为 `VRP-0`。
* 正文使用系统字体栈：`Segoe UI`、`PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei`、sans-serif。
* 标识、时间、代码、分数和 JSON 使用等宽字体或 tabular number。

| 色彩角色 | 当前用途 |
| --- | --- |
| Slate | 页面背景、正文、边框、次要文本、面板和表格 |
| Emerald | 主操作、选中状态、输入焦点和成功反馈 |
| Rose | 删除操作、错误反馈和危险状态 |
| Purple `#4d4397` | 品牌和桌面主导航激活状态 |
| Purple Highlight `#7569cc` | 求解结果分区标题与摘要标题，在品牌紫同色相上提高明度 |
| Blue / Orange / Green | 结果摘要、图表和业务状态区分 |

页面以浅 Slate 背景和白色实色面板为主。求解任务详情顶部的“基本信息”和求解曲线面板统一使用 Slate 50 底色，与下方白色 Gantt 工作区形成层次。新增样式复用已有语义色，不增加没有业务含义的主色。

### 2.1 字号层级

| 元素 | 字号 / 字重 |
| --- | --- |
| 页面标题 | `20px / 600` |
| 面板标题 | `17.5px / 600` |
| 正文与控件 | `16.25px` |
| 字段标签与表头 | `15px`，不做中文大写转换，不使用夸张字间距 |
| 普通指标 | `25px`；只有一张图大屏可使用更大字号 |

次要说明文字使用可读的 Slate 色阶；彩色背景中的文字必须选用对应的高对比度前景色。正文、操作名称和必要说明以 WCAG AA 对比度为目标。

上述字号和其余固定尺寸直接声明在 Host CSS、Scenario Shadow DOM CSS、Tailwind arbitrary value、内联样式或组件视觉常量中。浏览器默认根字号保持 `16px`，不得通过修改根 `font-size`、CSS `zoom` 或构建期全局换算间接改变密度。当前尺寸以 DPR 1.0 下复现原 DPR 1.25 物理观感为基准，因此旧固定尺寸原则上按 `1.25` 倍迁移；百分比、视口单位、业务数据和运行时坐标不参与换算。

## 3. 布局

* `app-shell` 占满视口，由应用控制整体和局部滚动。
* 桌面使用可折叠左侧导航；窄屏改用顶部移动导航。
* 页面滚动根边到边承载内容；`page-shell` 不额外绘制外框、圆角或页底留白，`panel-shell` 只用于必要的列表、详情和侧栏分区。
* 面板只保留一层白色实底和 `1.25px` 声明边框；相邻子区块共用单条分隔线：交界只由一侧绘制，禁止两个相邻边框叠加；应用顶栏与紧贴其下的工作区之间不绘制横向边框，贴页面边缘的面板不使用圆角。阴影只用于弹窗、浮层、菜单，以及需要与滚动结果区分层的求解任务详情工具栏；工具栏阴影保持轻量并只向下扩散。
* 表单采用手机单列、平板双列、`1600px` 以上按业务需要四列的响应式网格。标签与控件间距 `2.5px`，字段间距 `10px`，区块内边距通常为 `7.5–15px`；场景基础表单紧贴上下分隔线时，上下内边距收紧为 `5px`。
* 数据密集区域允许局部或横向滚动；工具栏以 `7.5px` 间距和 `7.5px 15px` 内边距组织，允许双语标签自然换行。
* 求解任务详情的“基本信息”、求解曲线和 Gantt 标题栏高度统一为 `60px`，并使用同一套字号、颜色和边界规则。

## 4. 通用组件

* 主按钮使用 Emerald 实底；次按钮使用白底和 Slate 边框；危险按钮使用 Rose 语义。普通按钮按内部文本自适应，图标按钮使用紧凑正方形尺寸；按钮栏距分区边界 `7.5–10px`。
* 输入框、下拉框和文本域使用一致的圆角、边框、背景、左右内边距和可见焦点状态。单行表单控件高度统一为 `37.5px`，以紧凑上下内边距使 `16.25px` 文本保持垂直居中；普通按钮为紧凑 `35px`；同行控件上下边缘对齐；短枚举、布尔和数值字段使用最小约 `120px` 的内容相称宽度，日期、地址和长文本保留可用宽度。
* 表格使用 `border-collapse`；每列声明自己的最小与最大宽度，预览态在该范围内按整列文本内容自适应，进入编辑态后锁定已经计算出的列宽，不能因输入控件替换预览文本而重排。表头、数据行和编辑行的横竖边线必须连续对齐。表头高 `45px`，普通及编辑行高约 `45px`，单元格垂直居中、内边距约 `2.5px 12.5px`。
* 宽表使用 `<colgroup>` 维护语义列宽范围和扩展权重：坐标按完整展示标准坐标值所需的宽度确定，内容够用后不参与剩余空间扩展；日期时间、枚举、布尔和操作等最长文本可确定的列，按中英文表头、最长展示值与编辑控件所需宽度设置紧凑上限，不参与剩余空间扩展；ID 和城市使用低权重，名称使用中等权重，地址和说明使用高权重，数值、状态与操作默认不参与扩展。数值列在空值或短值时使用紧凑最小宽度，再按当前表头与内容自适应到声明上限。内容期望总宽度超过视口但最小列宽仍可容纳时，从各列最小宽度开始，按权重优先满足仍被截断的信息列；内容均达到所需宽度后，剩余空间才按权重分配给显式可扩展且尚未达到最大宽度的数据列。某列到达上限后，其余空间继续分配给其他可扩展列，不增加无业务语义的填充列。保留全部列并只在指定容器内横向滚动。
* 地址、坐标、解析状态和位置操作在同一行。技能和已分配工单显示前两项及 `+N`；长 ID 渲染完整值，由实际可用容器以单行省略号截断。只有内容实际发生截断时才显示完整值提示，不为完整可见的 ID 重复提供提示。
* 场景表格中的坐标使用 Emerald 深色文字，地址使用可满足正文对比度的浅 Slate 文字；技能标签按技能文本稳定映射到同一组淡色背景、边框和深色前景，同一技能在车辆/工程师与工单表中保持同色。间隔行使用较浅的 Slate 50 背景；操作列按中英文操作文本紧凑收口，操作按钮水平居中，使左右到单元格边线的间隔相同。
* 场景约束表的权重输入框不使用圆角和独立外框；输入区域贴满权重单元格，由单元格边线作为控件边界，焦点反馈绘制在单元格内侧。
* 短状态使用圆角标签，并同时通过文字和颜色表达。场景配置导航使用“图标 + 文字”的扁平页签，不绘制胶囊外框；当前页签使用品牌紫色文字、图标和底部指示线，主操作仍使用 Emerald。
* 场景侧栏的可折叠模块在展开时使用品牌紫浅底、品牌紫标题和加粗字重，收起时保持白底与 Slate 标题；展开箭头同步旋转，不能只依赖颜色表达状态。
* 数值输入需要展示单位时，数值和不可编辑的文本后缀共用一个控件外框；后缀使用浅 Slate 背景和左分隔线，输入焦点反馈绘制在组合控件外框上。
* 弹窗或抽屉包含遮罩、可滚动内容区和明确关闭操作；删除等破坏性操作执行前确认。
* 悬浮提示只用于纯图标操作、未直接显示的必要补充说明，以及实际发生截断或折叠的内容；完整可见的标签、表头和值不重复配置提示。第一方控制台不使用浏览器原生 `title` 悬浮框，统一采用可控样式的提示；提示使用四边一致的浅色边框和主要向下扩散的轻阴影，避免上、左侧出现过重边缘。
* 成功和错误通知分别使用 Emerald 与 Rose，并包含可读文字。

页面专用组件的布局和交互由对应页面实现及[前端界面说明](../interfaces/frontend.md)维护，不在本文逐项复制。

## 5. 地图与图表

* 地图画布贴满内容区，不保留画布外层白边、额外内边距或重复边框；时间轴、工程师栏和地图之间仅使用单条分隔线。大屏工程师与指标以列表行或 Key/Value 分区呈现，不堆叠圆角卡片或阴影。
* 地图底图统一使用深色模式；HERE 使用原生夜间图层，AMap 使用原生 `darkblue` 主题，只有英文瓦片忽略主题时才对底图层应用兼容滤镜。一张图右侧工程师面板的当前任务、下一个任务值与工程师 ID 使用相同的等宽元信息字形。回放只重绘 Marker 与路线等业务覆盖物，地图语言和主题未变化时不得重复刷新底图瓦片。
* 地图不可用、没有路线或图表没有采样时显示文字状态，不用空白区域或伪造零值代替。
* 当前图表实现使用 Plotly；`lightweight-charts` 虽存在于前端依赖清单中，但当前页面代码未使用它。路线、Agent 和工单颜色在同一页面内保持一致。

## 6. 响应式与可访问性

* `1600px` 以下多列工作区改为纵向堆叠；页面负责纵向滚动，只有宽表、时间轴等指定区域横向滚动，页面自身不得产生意外横向溢出。
* 场景页签在窄屏横向滚动，帮助说明改为页签下方内联文字；场景宽表始终具有可见高度。移动地图画布高度不低于 `400px`。
* 交互使用 `button`、`input`、`select` 等语义元素；仅图标按钮提供可访问名称。
* 键盘焦点保持可见，状态和错误不能只依赖颜色。
* 中英文切换后，按钮和工具栏允许伸展或换行，不截断关键动作。

以上是维护约束，不表示所有历史页面已经经过完整可访问性审计。

## 7. 更新规则与非目标

视觉基础、通用组件或响应式规则变化时，按[文档总览的更新规则](../README.md#6-更新规则)更新本文。单一页面行为变化只更新页面实现、前端说明和对应测试。

本文不引入暗色主题、远程字体、动画框架、品牌重塑或新的视觉方向。
