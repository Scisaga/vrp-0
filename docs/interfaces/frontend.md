# 前端界面说明

## 1. 文档目的与边界

本文负责当前浏览器控制台的导航、页面职责、操作流程以及加载、空状态、错误和双语交互。

本文不定义后端 JSON 字段，不维护颜色和排版 token，也不提出页面重设计。视觉规则见[界面主题](../ui/theme.md)。

## 2. 应用框架与导航

控制台从根地址进入，使用 hash 路由和页面片段：

| 路由 | 导航可见性 | 页面职责 |
| --- | --- | --- |
| `#/scenario` | 主导航 | 维护当前场景并启动求解 |
| `#/solver-jobs` | 主导航 | 筛选和浏览任务历史 |
| `#/solver-job` | 隐藏 | 查看指定任务详情与结果操作 |
| `#/solver-map` | 隐藏 | 在地图与时间轴中查看指定任务 |
| `#/quota` | 主导航 | 查看和维护地图接口配置 |
| `#/mcp` | 主导航 | 查看 MCP 接入摘要、工具和运行状态 |

未知或空路由回到当前场景页。任务详情和一张图在导航中归属于任务列表。桌面导航保持扁平的四项结构；折叠侧栏只显示图标并保留可访问名称。窄屏使用顶部按钮展开移动导航。

## 3. 当前场景页

当前场景页承担单场景的完整录入和求解入口：

* 新建或导入页面草稿，以及读取、保存和删除当前场景；
* 维护场景概览、仓库、Agent、Ticket、SKU、约束和可用 Agent；
* 在表格中进行单元格编辑、增删行、技能编辑和位置维护；各列在自身最小、最大宽度范围内按预览文本自适应，空间不足时按语义权重优先扩展仍被截断的信息列，内容宽度满足后再分配剩余空间；坐标完整显示后不继续扩展，切换为编辑态时保持已计算列宽不变；
* 工单表的上一级和下一级工单标识以链接展示；点击已有工单标识后保持在工单页签，滚动并高亮对应工单行，关系字段仍通过独立编辑操作维护；
* 车辆/工程师、工单和 SKU 表格在载重/重量与容积/体积表头直接标注计量单位：重量使用吨，体积使用立方米；
* 通过地址解析、地图选点或直接编辑表格中的“坐标”单元格维护位置；直接输入按“经度,纬度”格式同步更新关联 POI 的位置与入口位置，不覆盖现有地址和城市；
* 导入包含场景的求解请求 JSON，或复制当前请求参数；
* 保存时选择是否生成在途矩阵；
* 配置求解时长及现有求解选项并创建任务；
* 在同一工作台切换到任务结果视图，执行停止、删除或返回列表。

创建视图顶部工具栏左侧保留“生成在途矩阵”和“规划求解”；右侧将“保存场景”及保存状态、独立的“导入”和“导出”按钮、删除操作依次分组，并用分隔线区分。“导入”打开求解请求 JSON 编辑弹窗，“导出”将当前请求参数复制到剪贴板；导入弹窗不提供手动格式化或全部折叠操作。窄屏时两侧操作允许换行，不能隐藏关键动作。

JSON 导入只替换页面草稿，不自动保存或启动求解。当前 Engine Host 后续普通保存和求解预保存都未携带 `replace=true`，因此不会按导入替换语义清理任务历史；只有显式调用替换语义接口或删除当前场景才会清理历史。页面提示必须与该行为一致。

车辆/工程师的燃料类型、油耗/电耗和每日固定成本不得按行号填入演示值。用户未提供且 OpenAPI Schema 没有明确默认值时，编辑单元格直接留空，不显示“未填写”或其他占位文案；构建请求时省略相应可选字段，不自动提交 `0` 或其他推测值。

Gateway 组件的创建校验结果在场景表格上方使用紧凑摘要展示：单项错误同行显示，多项错误展开为简短列表。用户可以手动关闭摘要；关闭只隐藏当前摘要，不清除组件校验 API 中的结构化错误，再次校验失败时摘要重新出现。界面只展示可执行的用户文案，不直接暴露 `request_payload.*` 等技术字段路径；结构化错误仍保留 `path` 和 `code`，供 Host 定位字段。

成本参数使用“数值输入 + 不可编辑单位后缀”的组合控件；单位后缀不进入场景数据。保底费按“元/车次”显示；比例按倍数显示，距离使用米，其他参数显示每车次、每节点、每次、每小时、每千瓦时或每升等已确认计量口径。除已明确为人民币的保底费外，页面不推断其他字段的币种；没有已确认计量单位的字段不显示单位后缀。

桌面端光标悬浮任一场景页签时展示该页签的帮助说明，不要求页签已选中；光标移出页签后隐藏说明。场景六个页签在窄屏横向滚动，帮助说明改为页签下方内联文字。宽表保留全部列并在局部容器横向滚动；右侧概览在小于 `1600px` 时排在主编辑区之后。

## 4. 求解任务列表

任务列表展示任务仓库中的历史任务摘要，支持按任务状态、创建时间、矩阵构建选项、矩阵方式和路线生成选项筛选；首次进入时创建时间范围默认取当前本地时间向前七日至当前本地时间，当前列表接口不再按来源场景标识额外过滤。筛选区按字段组响应式换行，每个参数名与对应控件同行、字号同为 `16.25px`，且组内间距小于字段组间距；只保留靠右的查询操作，不提供重置或手动刷新按钮；运行中任务仍按现有轮询规则自动更新。

每行显示任务名称、状态、求解时长、选项、求解分数、创建时间和求解完成时间，不展示任务 ID，并提供进入详情与一张图的操作。求解分数按 Hard、Medium、Soft 三段使用与求解曲线一致的红、橙、绿文字；求解完成时间仅对 `SOLVING_FINISHED` 任务显示，取该任务进入完成状态时的更新时间，列表不再重复展示更新时间列。任务列以 `10rem` 为最小宽度并按 `0.85fr` 参与剩余空间分配，使任务、状态、选项、分数和时间列按内容需求均衡扩展，避免任务名称右侧集中出现大段空白；列宽以展开桌面侧栏后的 `1600px` 视口为完整单屏基线，低于该基线时才由列表容器提供横向滚动。列表保留完整列结构和行点击行为。没有匹配任务时提示调整筛选或返回场景页创建任务。

## 5. 求解任务详情

任务详情按任务标识加载，主要包括：

* 任务状态、Hard 可行性/得分、约束数量和求解耗时优先展示，其次展示已有业务指标；
* 左侧“基本信息”、右侧求解曲线和 Gantt 统一使用 `60px` 标题栏；标题以品牌紫同色相、更高明度的紫色高亮代替粗体强调。顶部“基本信息”和求解曲线面板统一使用浅 Slate 底色，与下方白色 Gantt 工作区形成层次；任务状态胶囊紧随“基本信息”标题，原“结果状态”改为“求解信息”，Hard、Medium、Soft 得分分别使用与曲线一致的红、橙、绿文字；
* 分数过程与求解指标；
* 任务求解中时的运行状态占位；
* 任务结束后的甘特排程视图；
* 路线、工程师和工单侧栏；
* 约束说明、工单详情提示和业务标识复制；约束数量值与同列其他值左对齐，任务 ID 复制结果使用不占用内容流的全局悬浮通知；
* 矩阵模式、是否生成矩阵和是否绘制路线直接在左侧“结果状态”内，以与约束数量、求解耗时相同的两列 Key/Value 表格展示，不提供折叠交互；
* Hard 罚分使用带图标和说明的危险提示，不能只依赖文字颜色；
* 工具栏使用仅向下扩散的轻阴影与结果内容分层，不提供手动刷新、自动刷新开关或复制请求参数操作；
* 任务详情不提供“应用回场景”按钮；“停止求解”仅在 `SOLVING_SCHEDULED`、`SOLVING_ACTIVE` 可用，“删除任务”在运行中禁用，仅对可删除的终态任务开放。组件内按钮和 Engine Host 注入按钮遵循同一规则。

从场景页提交求解成功后立即进入对应任务详情。详情首次读取到 `SOLVING_SCHEDULED` 或 `SOLVING_ACTIVE` 时，每 5 秒在后台重新读取同一任务；进入任一非运行态、任务不存在或离开详情页时停止刷新。后台刷新复用当前任务标识，不切换到最新任务，也不提供用户可见的刷新开关。

求解结果摘要在接口原始数值后直接展示单位：总成本预估使用“元”，吨公里费使用“元/吨·公里”；英文界面分别使用 `CNY` 和 `CNY/t·km`。页面不额外展示币种说明。

任务详情首次请求完成前展示加载状态，不能提前闪现“当前没有求解任务”；请求完成后，任务不存在、任务无最终方案或当前仍在求解时，应分别展示错误、空状态或运行中状态，不渲染误导性的结果图表。

## 6. 求解任务一张图

一张图把结果路线、Agent、工单和时间轴组合展示：

* 任务上下文和状态；
* 地图上的路线、位置与 Agent 状态；
* Agent 选择和任务统计；
* 回放时间、播放控制和时间调整；
* 没有路线、地图不可用或数据加载失败时的替代状态。

回放时间轴从最早的已派单车辆由仓库出发时刻开始，到所有已派工单中最晚的服务结束时刻为止。场景规划起止、班次结束和返仓完成时间不扩展播放区间，时间轴的首尾刻度与实际播放边界一致。

页面只展示任务中已有的求解与路线数据，不在浏览器重新求解或自行修正任务状态。默认地图不展示全部工单长 ID；只有聚焦某位工程师时展示其工单标签。工程师标记优先使用名称，否则使用短 ID，完整 ID 保留在标题或详情中；列表的路线、聚焦和显示使用带完整 `aria-label` 与状态提示的紧凑图标切换组。右侧工程师面板中的当前任务、下一个任务值与工程师 ID 使用相同的等宽元信息字形。大屏焦点详情中的“下一个任务”在指向实际工单时可点击，并复用详情侧栏的工单定位行为跳转到场景页。

所有地图使用深色底图。一张图播放时重新绘制 Marker 与路线等业务覆盖物；地图实例、语言和主题没有变化时复用当前底图，不重复设置样式或刷新地图瓦片。

大屏顶栏将当前焦点对象与跟随视角开关相邻展示；跟随开关保持固定位置并以按下状态表达正在跟随，随后依次分组展示地图视角操作和页面导航操作。

移动端依次展示地图、时间轴和工程师面板，地图画布高度不低于 `400px`。

## 7. 地图接口页

地图接口页读取并保存当前 AMap 适配器的密钥、QPS、总配额、统计周期、超时和地址解析选项。移动端顺序为表单、预览、说明。API Key 默认使用密码输入框，用户可显式显示或隐藏；JSON 预览始终只渲染固定掩码，保存请求仍提交原始表单值。

真实敏感值不得进入前端源码、截图或文档示例；部署环境是否允许访问该页由应用外部入口控制。

## 8. MCP 接入页

MCP 页面展示：

* 是否启用、传输方式和认证模式；
* 当前 MCP 地址和复制操作；
* Tool 分组与典型调用流程；
* Harness、VS Code 和 Codex 的客户端配置片段；
* Origin 允许列表与使用说明；
* 打开 MCP 参考文档的入口。

页面只显示 Token 占位符，不读取或展示真实 Bearer Token。Tool 的精确定义以 [MCP 参考](../reference/mcp.md)为准。

MCP 信息使用紧凑行和单层面板，不使用 24px 大字或嵌套卡片。移动端依次展示接入摘要、工具与工作流、客户端配置、状态与说明，所有区域随页面纵向滚动可达。

## 9. 移动端内容顺序

`488×1055` 下采用“页面纵向滚动、局部宽表横向滚动”。求解结果依次展示摘要、曲线、Gantt 和工程师详情；配额与 MCP 顺序见对应章节。`960×1280` 以下仍不得因多层 `overflow-hidden` 造成核心区域不可达。

## 10. 通用交互状态

### 10.1 初始化与加载

应用框架加载页面片段前显示初始化状态。列表、任务详情、地图和配置页按现有实现显示加载状态；提交类操作在请求期间禁用对应按钮。应用启动时异步获取并缓存当前 `map_context`，同时预连接图商域名并预热 AMap SDK；地图选点、任务路线预览和一张图在同一页面会话中复用该上下文与 SDK 加载结果，预热失败不阻塞非地图界面，实际地图初始化仍负责显示错误状态。

### 10.2 空状态

空状态必须说明当前缺少什么以及可采取的下一步，例如录入当前场景、调整任务筛选或等待任务产生结果。空状态不能用空白表格代替。

### 10.3 成功与错误

短时操作反馈使用页面通知或全局通知；可恢复错误允许用户关闭后继续操作。删除场景、删除任务等破坏性操作先确认。

前端 API 工具根据后端稳定错误码和参数生成双语提示；服务端 `message` 只用于未知错误的安全兜底。

### 10.4 双语

框架提供简体中文和英文切换，当前语言用于导航、页面文案、状态、错误和时间格式。新增用户可见字符串必须进入现有 i18n 字典，不能只在一种语言中硬编码。

### 10.5 日期与时间输入

所有包含时间的日期输入控件统一使用 24 小时制（`00:00`–`23:59`），不显示或输入 AM/PM。控件以单一输入框显示 `YYYY-MM-DD HH:mm[:ss]`，支持直接输入和粘贴；日历图标打开“左侧月历、右侧时/分/秒滚动列”的日期时间浮层，选择后经“确定”一次写回。秒级控件显示秒列，分钟级控件只显示时、分列；纯日期输入保持现有行为。
