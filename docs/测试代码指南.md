# 测试代码指南

本文档记录本项目测试代码的分类、覆盖重点和编写约定。目标是让测试既能覆盖 VRP 核心业务正确性，也能保持默认门禁稳定、快速、无外部依赖。

## 测试代码目录结构

测试代码按“测试类型 + 被测模块”组织。

推荐结构：

```text
src/test/java/
  unit/
    one/rewind/...
  app/
    one/rewind/...
  integration/
    one/rewind/...
  manual/
    one/rewind/...
  support/
    one/rewind/...
```

目录语义：

- `unit/`：稳定单元测试，不启动 Quarkus，不访问真实外部服务，由 `test` 运行。
- `app/`：Quarkus 应用测试，测试类统一标记 `@Tag("app")`，由 `appTest` 运行。
- `integration/`：外部集成测试，测试类统一标记 `@Tag("external")`，由 `externalTest` 或 `integrationTest` 运行。
- `manual/`：手工/脚本测试，测试类统一标记 `@Tag("manual")`，由 `manualTest` 运行。
- `support/`：测试辅助代码、fixture builder、外部测试 skip helper，不直接放 `*Test`。

按模块细分示例：

```text
src/test/java/
  unit/
    one/rewind/amap/
    one/rewind/xforce/geo/
    one/rewind/xforce/json/
    one/rewind/xforce/vehicle_routing/domain/
    one/rewind/xforce/vehicle_routing/solver/
    one/rewind/xforce/vehicle_routing/service/
    one/rewind/xforce/vehicle_routing/store/

  app/
    one/rewind/xforce/vehicle_routing/db/repository/
    one/rewind/xforce/vehicle_routing/mcp/
    one/rewind/xforce/vehicle_routing/rest/
    one/rewind/xforce/vehicle_routing/service/

  integration/
    one/rewind/amap/
    one/rewind/xforce/geo/
    one/rewind/xforce/vehicle_routing/remote/
    one/rewind/xforce/vehicle_routing/rest/

  manual/
    one/rewind/xforce/vehicle_routing/bootstrap/
    one/rewind/xforce/vehicle_routing/report/
    one/rewind/xforce/vehicle_routing/solver/

  support/
    one/rewind/xforce/test/
```

测试资源建议放在：

```text
src/test/resources/
  fixtures/
    scenarios/
    pois/
    matrices/
    solver_jobs/
  app/
  external/
```

资源目录语义：

- `fixtures/`：稳定测试数据，必须小而明确。
- `fixtures/scenarios/`：scenario JSON。
- `fixtures/pois/`：POI fixture。
- `fixtures/matrices/`：TransitMatrix fixture。
- `fixtures/solver_jobs/`：solver job fixture。
- `app/`：Quarkus 应用测试专用资源。
- `external/`：外部集成测试说明或非敏感样例配置，禁止提交密钥。

命名示例：

```text
TicketDomainTest.java
AgentEachDayDomainTest.java
RoutePlanConstraintProviderTest.java
ArrivalTimeUpdatingVariableListenerTest.java
ScenarioRepositoryTest.java
ScenarioResourceTest.java
McpServerTest.java
AmapAdapterExternalTest.java
ScenarioCreateRemoteExternalTest.java
```

测试辅助类不应散落在业务测试包中，应放到 `support/`。

## 测试分层

### 单元测试

用于验证纯 Java 业务逻辑，不启动 Quarkus，不访问真实外部服务，不读写生产数据目录。

应覆盖：

- 领域模型：`Agent`、`AgentEachDay`、`Ticket`、`RoutePlan`、`Scenario`、`SolverJob`。
- 计算逻辑：装载、行驶时间/距离、完成时间、时间窗、改派判断、可用工程师窗口。
- JSON 与引用归一化：对象 ID、互相引用、重复对象、缺失字段、序列化往返。
- 存储工具：路径解析、临时目录读写、文件缺失、异常输入。
- Solver 辅助逻辑：shadow variable、move filter、权重工厂、timeline 构造。

单元测试必须有明确断言。禁止只打印对象、只执行方法、只依赖“不抛异常”作为测试结果。

### Solver 约束测试

Solver 约束是本项目核心业务规则，应使用 `ConstraintVerifier` 或等价方式单独测试，不依赖 REST 或完整求解流程。

每个约束至少覆盖：

- 一个非零惩罚/奖励路径。
- 一个不触发路径。
- 关键边界数据：未指派 ticket、虚拟 agent、空技能、空资质、空时间字段、空矩阵。
- justification 不抛异常，尤其是未指派或不完整业务对象。

重点覆盖：

- 硬约束：容量、最大接单、技能匹配、资质匹配、同网点、依赖工单先后、依赖工单同 agent、跨日指派。
- 中/软约束：时间窗迟到、关联工单同 agent、虚拟工程师、固定成本、行驶时间、行驶距离、负载均衡、工时均衡、改派惩罚。

### Quarkus 应用测试

用于验证应用内 REST、repository、service、MCP 协议等需要 Quarkus 容器的行为。测试类应标记 `@Tag("app")`，由 `appTest` 运行。

应覆盖：

- REST 契约：状态码、错误码、响应结构、幂等性。
- 服务状态流：scenario 创建/替换/删除，solver job 启动/终止/完成/删除。
- 运行中保护：solver job running 时禁止修改 scenario。
- repository：当前对象、历史对象、矩阵持久化、状态 reset、metrics append。
- MCP：鉴权、tools/list、tools/call、错误返回、与 REST 状态一致性。

Quarkus 测试必须使用 `%test` 配置和测试目录，不能写生产 `data/`。

### 外部集成测试

用于验证 AMap、HERE、远程地址解析、远程部署 API 等真实外部依赖。测试类应标记 `@Tag("external")`，由 `externalTest` 或 `integrationTest` 运行。

外部集成测试默认不进入稳定门禁。必须显式开启：

```bash
./gradlew externalTest -Dvrp.external.enabled=true
```

或：

```bash
VRP_EXTERNAL_TESTS=true ./gradlew externalTest
```

应覆盖：

- AMap query、geocode、reverse geocode、routing、truck routing。
- HERE Matrix 真实联调只能覆盖 `1×3` 和 `2×3`：先 `set -a && source .env && set +a` 导出 `HERE_API_KEY`，再设置 `VRP_EXTERNAL_TESTS=true`。不得以大矩阵做真实请求；大矩阵、异步与分片仅使用 fixture 单元测试。
- 地址解析服务成功、失败、fallback、禁用 fallback。
- 远程 API 创建 scenario、启动 solver、轮询完成。
- key 无效、quota exhausted、网络超时、服务不可达。

测试前置条件不满足时应 skip，不应失败。

### 端到端场景测试

用于验证少量真实业务流程。数量应少，fixture 固定，求解时间受控。

应覆盖：

- 创建小型 scenario。
- 构建本地矩阵。
- 启动 solver。
- 获取求解结果。
- apply 结果。
- 查询 scenario。
- 删除 scenario 后 solver job 清理。
- 替换 scenario 后旧 job 不污染新 scenario。

默认端到端测试应避免真实外部服务。需要外部服务的端到端测试归入外部集成测试。

### 手工/脚本测试

用于调试、生成图表、打印方案、探索数据，不作为默认质量门禁。测试类应标记 `@Tag("manual")`。

手工测试可以保留输出，但不能放在默认 `test` 或 `appTest` 中。

## Gradle 入口

常用入口：

```bash
./gradlew test
./gradlew appTest
./gradlew externalTest
./gradlew manualTest
./gradlew allStableTest
```

入口语义：

- `test`：默认稳定单元/轻量测试，排除 `app`、`external`、`manual`。
- `appTest`：运行 `@Tag("app")` 的 Quarkus 应用测试。
- `externalTest`：运行 `@Tag("external")` 的外部集成测试。
- `integrationTest`：外部集成测试兼容别名。
- `manualTest`：运行 `@Tag("manual")` 的手工/脚本测试。
- `allStableTest`：运行 `test` 和 `appTest`。

默认提交前至少运行：

```bash
./gradlew test appTest
```

## 编写约定

### Fixture

稳定测试使用小型 fixture。fixture 应放在：

```text
src/test/resources/fixtures/
```

测试数据要求：

- 尽量小。
- 只包含当前测试需要的数据。
- 不依赖本机绝对路径。
- 不依赖真实外部服务。
- 不写生产目录。

### 时间

不要使用 `LocalDateTime.now()` 作为业务断言基础。应使用固定时间：

```java
LocalDateTime.of(2026, 1, 2, 8, 0)
```

只有测试系统时间本身时才允许使用当前时间。

### 文件与目录

测试读写文件必须使用临时目录或 `%test` 配置目录。禁止写入：

```text
data/
scenarios/
```

除非该测试被归入 `manual`。

### 外部服务

默认测试禁止真实调用：

- AMap。
- 地址解析服务。
- 远程部署环境。
- 生产 API。

需要外部服务的测试必须：

- 标记 `@Tag("external")`。
- 使用显式开关。
- 前置条件不满足时 skip。
- 不泄露 key。

### 日志

默认测试不应产生大量无意义输出。负向路径可以触发异常，但应尽量断言错误结果，而不是依赖异常栈出现在日志中。

## 回归测试要求

每次修复缺陷都应添加最小回归测试。优先覆盖：

- ticket ID 与 agent ID 冲突。
- 未指派 ticket 的 solver justification NPE。
- `AgentEachDay` 字段复制遗漏。
- incomplete matrix 仍可读取。
- solver exception 映射策略。
- scenario 替换后旧 solver job 清理。

回归测试应尽量进入默认 `test` 或 `appTest`，除非缺陷只发生在真实外部服务中。

## 覆盖优先级

新增测试优先级：

1. Solver 约束与 shadow variable。
2. 领域模型计算逻辑。
3. 服务层状态流。
4. JSON 引用和 repository 持久化。
5. REST/MCP 契约。
6. 外部集成。
7. 手工脚本。

项目质量风险主要集中在 solver/domain/service，因此这些层级的测试应优先补齐。
