# 安全边界

## 1. 文档目的与边界

本文负责说明当前 REST/MCP 调用边界、Bearer Token、Origin 与 CORS、地图密钥、日志脱敏、文件访问和错误信息安全。

本文不声称存在尚未实现的用户账号、角色或租户权限体系，也不设计部署平台的网络拓扑。

## 2. 调用边界

* REST 与静态控制台由同一 Quarkus 应用提供。当前应用代码没有独立的 REST 用户身份或角色模型，生产暴露范围必须由部署网络、入口代理或上游系统控制。
* MCP 是独立的可开关入口，默认关闭；启用后由 MCP 认证过滤器保护。
* REST 和 MCP 最终操作同一份当前场景和任务数据，MCP 认证不会自动给 REST 增加认证。
* 静态页面只能通过 HTTP 接口访问数据，不应直接读取服务器文件目录。

## 3. MCP Bearer Token

* MCP 实际请求必须携带 `Authorization: Bearer <token>`。
* 缺少 Authorization、格式错误和 token 不匹配分别返回拒绝，不进入 Tool 调用。
* token 比较使用常量时间比较，降低基于比较耗时的泄露风险。
* 浏览器的 `OPTIONS` 预检允许先通过 Bearer 过滤器，再由跨域规则处理。
* MCP 启用时 token 不得为空；默认示例值不能用于真实部署。

精确接入方式见 [MCP 参考](../reference/mcp.md)。

## 4. Origin 与 CORS

* `vrp.mcp.allowed-origins` 非空时，MCP Streamable HTTP 只接受允许列表中的浏览器 Origin。
* 空的 MCP Origin 列表表示不额外启用 MCP Origin 允许列表，不等同于关闭 Bearer 认证。
* Quarkus REST 当前启用 CORS，并允许配置中的广泛来源、常用请求头和 `GET/PUT/POST/DELETE`。生产部署应根据实际入口收紧，而不是把开发默认值视为安全边界。
* 允许凭据时必须同时审查来源配置，不能只依赖浏览器端限制。

## 5. 地图密钥与配置

* 服务端地图密钥由运行配置或环境注入，不提交到仓库，不写入文档示例的真实值。
* 配额与密钥配置接口属于敏感管理能力；在没有应用内角色控制的情况下，应由部署入口限制访问。
* 浏览器地图上下文可能需要下发浏览器侧地图 key。部署方必须在地图平台限制允许域名和 API 权限，并使用专用于浏览器的受限凭据。
* 示例配置中的空值或 `change-me` 只是不可用占位符，启动生产实例前必须通过受控配置注入真实凭据。
* 自建地址解析器默认只使用回环地址示例；选择 `ADDR_RESOLVER` 前必须显式配置受信任端点。

## 6. 日志和错误

* MCP Token、地图密钥和完整 Authorization 头不应写入日志；当前实现没有统一的日志脱敏层。
* 求解回调 URL 和对端响应当前会被记录，回调地址不得携带密钥等敏感查询参数。
* 对外业务错误使用稳定的 `error_code` 和 `error_params` 表达可处理原因；控制台据此本地化。
* 通用未预期异常映射为内部错误，响应当前包含异常类名和 `message`，不包含完整堆栈。
* `SolverJob.exception` 当前使用 `ThrowableProxy` 持久化并对外序列化，可能包含堆栈、类名和内部消息。REST 未提供应用内访问控制，因此任务接口不能直接暴露到不受信任网络。

当前实现不能保证错误和任务异常已经完整脱敏。变更异常结构或扩大接口暴露范围前，应先收敛对外字段并补充脱敏测试。

## 7. 文件访问

* 场景和任务目录由服务进程账号读写，部署时按最小权限授予目录访问。
* 存储路径由配置解析并规范化；业务标识只作为受控任务目录名使用。
* HTTP 接口不提供任意文件路径参数，也不直接暴露场景或任务文件。
* MCP 参考文档端点只查找固定的 `docs/reference/mcp.md` 相对路径。
* 数据卷可能包含完整业务场景和求解结果，应按业务数据对待并限制宿主机访问。

## 8. 变更检查

认证、Origin/CORS、密钥、日志、错误或文件访问边界变化时，按[文档总览的更新规则](../README.md#6-更新规则)同步文档和测试。

## 9. 非目标

本文不定义用户管理、RBAC、租户隔离、审计平台、密钥托管产品或网络防火墙方案；不能把部署建议误写成应用已实现能力。
