# 数据存储

## 1. 文档目的与边界

本文负责说明当前场景、求解任务和在途矩阵的文件目录、内容拆分、锁、原子写入、启动恢复、删除和大对象裁剪规则。

本文不定义业务字段全集、备份平台、数据库迁移或跨实例一致性方案。

## 2. 存储根目录

默认目录由运行配置决定：

* `vrp.scenario.store.dir=./data/scenarios/`
* `vrp.solverjob.store.dir=./data/solver_jobs/`

相对路径从进程工作目录向上查找项目根标志，并相对找到的项目根解析；找不到项目根时才相对工作目录解析。测试 profile 改用 `./build/test-data/` 下的隔离目录。部署时应将两类目录放在可写且需要持久化的卷上。

## 3. 当前场景布局

```text
<scenario-store>/
└── current/
    ├── scenario.json
    ├── meta.json
    └── matrix.json.gz       # 矩阵存在且非空时生成
```

* `scenario.json` 保存当前场景主体；写入时从 `RoutePlan` 临时移除矩阵。
* `meta.json` 保存场景标识、名称和创建、更新时间。
* `matrix.json.gz` 单独保存完整在途矩阵。
* 读取时装配元数据与矩阵，归一化对象引用并调用 `RoutePlan.init()`。

仓库只检查 `current` 目录，不扫描或暴露场景列表；`count()` 只可能返回 0 或 1。

## 4. 求解任务布局

```text
<solver-job-store>/
├── index.json
└── jobs/
    └── <job-uuid>/
        ├── job.json
        ├── meta.json
        └── matrix.json.gz   # 任务方案包含矩阵时生成
```

* `index.json` 保存任务摘要列表和 `latestJobId`。
* `job.json` 保存任务主体、状态、方案、异常对象和过程指标，不内嵌矩阵；异常对象当前可能包含堆栈信息。
* `meta.json` 保存任务索引所需的元数据。
* `matrix.json.gz` 保存任务方案的矩阵。
* 列表查询主要读取索引摘要；读取具体任务时再装配主体和矩阵并初始化方案。

删除最新任务后，仓库根据剩余索引更新 `latestJobId`；删除全部任务会清理任务目录和索引内容。

## 5. 并发与原子写入

`ScenarioRepository` 和 `SolverJobRepository` 分别使用进程内 `ReentrantReadWriteLock`：读取持有读锁，保存、更新状态和删除持有写锁。

JSON 和 gzip JSON 的写入流程为：

1. 确保父目录存在。
2. 在目标目录创建临时文件并完整写入内容。
3. 优先使用 `ATOMIC_MOVE` 替换目标文件。
4. 文件系统不支持原子移动时，回退为普通替换移动。

该机制降低单文件部分写入风险，但进程内锁和本地文件替换不提供多个应用实例共同写同一目录时的协调能力。

## 6. 更新与删除语义

* 保存当前场景覆盖 `current` 目录内的主体、元数据和矩阵；没有有效矩阵时删除旧矩阵文件。
* 按替换语义保存或删除当前场景时，应用门面同时清理求解任务历史。
* 求解过程中，更优方案、搜索采样、完成状态和异常状态会更新对应任务文件与索引。
* 正在运行的任务在业务层被禁止删除。
* 删除操作遍历并移除仓库受管目录内的内容，不操作存储根目录之外的路径。

## 7. 启动恢复

启动时仓库从现有文件按需恢复场景和任务。部署初始化逻辑把遗留的 `SOLVING_SCHEDULED` 和 `SOLVING_ACTIVE` 任务改为 `NOT_SOLVING`，表示原进程中的求解不会在重启后续跑。

读取任务或场景时会重新装配矩阵、规范化引用并初始化规划模型。损坏的 JSON 或 gzip 内容以及目录不可写会作为存储错误暴露；缺少元数据或矩阵文件时按缺失数据处理，不猜测性重建内容。

## 8. 大对象边界

* 矩阵从场景和任务主体 JSON 中拆出并压缩保存。
* 任务列表只读取摘要，不为每行装配完整方案和矩阵；摘要索引随任务保存当前最佳或最终得分，首次列表读取会从旧版任务主体补齐尚未进入索引的历史得分。正常完成时间由 `SOLVING_FINISHED` 状态下的更新时间派生，不单独持久化第二个时间字段。
* 场景和任务矩阵随各自主体由对应 Repository 装配和保存。REST/MCP 的 `/matrix`、`get_matrix` 与 `set_matrix` 只读写 `AmapTransitCalculator` 的进程内路由缓存，不直接读写场景或任务存储中的矩阵文件；该缓存本身不由上述 Repository 持久化。
* 搜索过程采样只追加指标，不携带 `RoutePlan`，避免覆盖更优方案或放大写入量。

## 9. 非目标

本文不规定数据库替代方案、备份周期、对象存储、跨区域复制或多实例共享写入方式。
