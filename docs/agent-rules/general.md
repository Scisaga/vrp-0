# 通用开发规则

## 1. 文档目的与边界

本文负责项目级开发规则、变更边界、测试要求和完成定义，供开发者与 agent 在每次任务开始前使用。

本文不定义产品需求、接口字段、求解约束细节或部署参数；应从[文档总览](../README.md)进入对应专题文档。本文也不授权新增未确认能力。

## 2. 开始任务前

1. 先确认任务影响的产品、需求、设计、接口、页面、测试或部署范围。
2. 按[文档总览](../README.md)读取对应事实源，不以相邻模块的实现推断目标模块行为。
3. 检查工作区已有改动，区分用户改动与本次任务改动，不覆盖、不重排无关内容。
4. 如实现需求尚未进入对应权威文档，先补充文档再修改实现。
5. 对无法由代码、配置、契约、测试或用户确认事实支持的内容，先询问，不直接猜测。

## 3. 变更规则

* 只完成用户要求的局部目标；不借机重构、迁移、重命名或格式化无关文件。
* 保持一个运行实例只有一个当前场景的既有边界，除非用户明确改变该口径。
* 不新增接口、配置、状态、约束、存储结构或产品能力来填补文档空白。
* 接口或模型代码影响 OpenAPI 时，同步维护 OpenAPI 注解并更新 `docs/openapi.yaml`。
* 只改说明性文档且接口契约未变化时，不改写 `docs/openapi.yaml`。
* 文档的详细事实写入负责该事实的专题文档；其他文档只保留摘要和链接。
* 不修改 `build/` 等生成产物，不提交 token、API key、密码或环境专用生产配置。

## 4. 测试规则

* 对外可见行为变化必须补充或更新相应测试。
* 默认稳定门禁是 `./gradlew allStableTest`，包括单元测试和进程内应用测试。
* 外部地图测试必须显式启用，使用受控的小规模请求，不能进入默认稳定测试。
* 文件存储测试使用隔离目录，不读写开发或生产数据目录。
* 静态页面变化按[测试说明](../operations/testing.md)运行对应 Node 或 Playwright 测试。
* 纯文档变更至少执行 Markdown 链接、标题层级、术语一致性和 `git diff --check` 检查；不强制运行代码测试。

## 5. 文档联动

按[文档总览的更新规则](../README.md#6-更新规则)检查受影响文件，不在本文重复维护联动矩阵。

## 6. 完成定义

任务完成必须同时满足：

1. 改动范围与用户要求一致，没有无关扩展。
2. 实现、配置、契约和专题文档表述一致。
3. 应运行的测试和静态检查已通过，或明确说明未运行及原因。
4. 所有新增或修改的文档链接有效、标题层级正常、术语一致。
5. 未提交生成文件、密钥或环境专用数据，未覆盖工作区中的既有用户改动。

## 7. 非目标

本文不规定新的架构、工作流平台或审批机制，也不把建议性事项写成当前已实现能力。
